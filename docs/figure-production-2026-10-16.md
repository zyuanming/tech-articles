# 技术图的生产与自检

2026-10-16 起，本库新增文章的程序绘图按本页执行。它记录的是这一批文章实际用到的做法与踩过的坑，不是通用设计规范，也不回写历史成稿。

## 为什么需要自检

写图的人和看图的人是同一个（或同一个模型）。手工画完直接交付，最常见的失败不是"不好看"，而是这几类**画的人自己看不见的错误**：

- 一段文字画到了画布外面，PNG 里根本没有这些像素；
- 文字越出了它所属的圆角框，压在框线上；
- 两个标签叠在一起；
- 字号在手机宽度下读不出来；
- 文字颜色和底色对比度不够，等于没写；
- 画布底部留一大块空白，读者以为图没加载完。

这些都不是审美问题，是可以被判定的几何与像素问题。所以本批文章的做法是：**把判定写成代码，图过不了就不许保存。**

## 一、先分配足够大的画布，最后按内容裁

固定高度模板是坏图的头号来源。做法反过来：

1. 建画布时一律分配一个足够高的位图（本批用 4000 像素）。
2. 每画一段文字、一个框，就记下它的实际像素包围盒。
3. 保存前按"最后一个内容 + 边距"裁剪；如果内容反而超出了，就往下扩展。

这样图的高度永远由内容决定，不会出现底部空白，也不会出现"画到画布外面"。

## 二、保存前必须过的五项检查

| 检查 | 判据 |
|---|---|
| 出界 | 每段文字的包围盒必须完全落在画布内 |
| 越框 | 声明了归属框的文字，包围盒必须在框内并留出边距 |
| 重叠 | 任意两段文字包围盒不得相交（可逐段显式豁免，例如 diff 输出里的空行） |
| 字号 | 设计字号下限 40 像素；1062 像素宽的画布按 354 像素显示折算，有效字号约 13.3 像素 |
| 对比度 | 文字包围盒内最亮与最暗的亮度差必须够大，防止"白字画在白底上" |

再加一项像素审计：每段文字的实际区域必须有足够多的非背景像素——用来抓住"字体里没有这个字形，画出来是一片空白"这类错误。

## 三、符号字形要先验证存在

用 Unicode 画棋子、箭头、数学符号时，中文字体里未必有这些字形，缺字时画出来是豆腐块或空白。做法是：**符号单独指定一款符号字体，并在使用前先渲染一次，确认它的像素与私用区码位的渲染结果不同**。本批文章的 `glyph_available()` 就是这个检查。

中文字体的查找按候选列表依次尝试，全部找不到时**直接报错退出**，不退回默认字体——默认字体画不出中文，退回去等于静默产出坏图。

## 四、柱子长度必须由数值算出来

同一张图里出现两个独立缩放的量纲，会让小数字的柱子比大数字的长，图就在说谎。规则：

- 全图共用一根轴、一个最大值；
- 柱子长度由 `数值 / 最大值` 算出，不手写；
- 画完断言一次：**把每根柱子的像素长度和它的数值各排一列，两列的排序必须一致。**

## 五、真实素材的放法

- 第三方真实照片放在 `originals/photos/`，`assets/` 只放正文图与封面。
- 照片按"覆盖填充"缩放：等比放大到刚好盖住目标矩形，再居中裁切，**不拉伸**。
- 超过每图 5,000,000 字节的原件，另存私有备份，发布用副本做最小必要缩放并记录；原始尺寸本身很小的历史文件不得放大后称其为高清。
- 真实照片与原创示意在同一张图里合成时，只做版面排布，不改动照片内容。

## 六、图和代码的关系

本批文章的每一张图都由 `examples/build_figures.py` 生成，图里的数字从 `examples/` 里实测的 JSON 读取，不手写。这样"正文里的数"和"图里的数"和"代码跑出来的数"是同一个来源，改一处不会让另外两处悄悄过期。

每张图在 `examples/figure-metadata.json` 里记下尺寸、最小字号、用途与身份（原创示意 / 模型输出 / 第三方照片）。生成后应逐项核对：元数据里的宽高与 PNG 实际宽高一致，`read.md` 引用的每个文件都存在，且没有未被引用的图。

## 七、改正文里的数字时，图必须一起查

2026-10-16 这一批踩到的真实坑：正文里一处比例写错了，改成正确值之后，**同一句话还印在图里**。独立审读第一遍只看正文，放过了；第二遍把图重新生成并做了一次 OCR，才发现图里还是旧数字，于是正文和图对同一件事给了两个答案。

原因很简单：图里的说明文字是绘图脚本里的字面量，它和正文各存一份。改了一处，另一处不会跟着变。

所以：

- **正文里任何被修正的数字，都要回头在 `build_figures.py` 里搜一遍。** 改完重新生成 PNG，并确认新 PNG 与旧的不同。
- 提交前做一次**图内数字清点**：把绘图脚本里所有含数字的中文说明字面量抽出来逐条读一遍，和正文、和实测数据对。三篇文章一共 173 条，人工过一遍不慢，漏掉的代价是读者看到两个互相矛盾的数。
- 同一句话不要在图和正文里各写一份。能让图从数据算出来，就让图去算；只能手写的说明，改正文时按上面的办法同步。

同一类问题还有一种更隐蔽的形态：**结论被削弱了，但图里的标题还留着旧结论。** 本批 diff 那篇的图 19 标题原本印着「2007 年：换一个目标」，而正文里的年份因为核不到原始来源已经删掉了。图注同样要跟着事实范围走。

## 八、自检能抓什么、抓不到什么

能抓：出界、越框、重叠、字号、对比度、缺字、柱子顺序、空白底边、元数据不一致。

**抓不到**：图讲得对不对、读者能不能看懂、数值有没有被误解、视觉层级是否合理。这些仍然要由独立审读的人对照正文逐张看，并回答"这张图删掉，读者会损失什么"。自检通过不等于图合格。
