# # 同样的跳跃，30 帧跳矮了 13 厘米

同一段跳跃代码，60 Hz 上跳 1.000 米，30 Hz 上 0.933 米，240 Hz 上 1.050 米，而连续解是 1.067 米。这一篇从这两行积分代码出发，量清楚「一帧算多久」是怎么变成物理参数的：最高点、累加器补帧、死亡螺旋的稳态公式、薄墙穿透率、三种积分器的能量账、float32 累加一小时的 2.79 秒，最后是为什么固定 dt 也不等于可复现。

## 复现

```
python3 examples/run_model.py      # 生成 examples/results.json（约 0.3 秒）
python3 examples/build_figures.py  # 生成 assets/ 与 cover.png（约 3.4 秒）
```

两个脚本都是确定性的，重跑得到逐字节相同的数字与图。只用标准库：随机数是自己写的 SplitMix64（Steele–Lea–Flood 的 splitmix64），不是 Python 内置 `random` 的实现细节；float32 用 `struct` 往返模拟，不依赖 numpy。

## 关于数字

正文里每一个数都来自 `examples/results.json`，图也一样。五处可以手算复核：

1. 跳一手算：v0 = 8、g = 30、dt = 1/60，每帧速度减 0.5，第 k 帧走 (8−0.5k)/60 米。16 帧走到掉头，和是 (7.5+7+…+0)/60 = 60/60 = 1.000 米。把两行换个顺序，同样 16 帧走 (8+7.5+…+0.5)/60 = 68/60 = 1.1333 米，两个数对连续解 1.0667 各偏 0.0667 = v0·dt/2。
2. 死亡螺旋稳态：每帧基础 20 ms、每步 c ms、dt = 1/60，则 t = 20/(1−c/16.67)。c = 10 给 50 ms（实测 48.5），c = 16 给 500 ms（实测 482.5）；c = 16.67 分母为零。
3. 插值的连续时间等价：每帧 10% 对应 λ = −ln(0.9)×60 = 6.3216 /s，半衰期 ln2/λ = 0.1096 秒；144 fps 下等价系数 1−e^(−6.3216/144) = 0.04295。
4. 穿透闭式：墙厚 0.1、dt = 1/60，每步位移 v/60；穿透率 ≈ 1 − 0.1/(v/60)。v = 40 给 0.85，实测 0.840（200 次试验的抽样误差）。
5. 浮点：float32 在 1800 附近的 ulp 是 2⁻¹³ = 1.22×10⁻⁴ 秒，1/60 秒 = 136.5 个 ulp，每帧舍掉约半个 ulp；216000 帧累计 −2.79 秒。

模型没做的事：任何真实引擎的帧时间序列、GPU/驱动的 vsync 行为、网络同步的实际抖动、真实 CPU 的 FMA/x87 差异。这些只作为背景出现，`sources.md` 里逐条写明哪些是设定值、哪些没算、哪些是文献。所有数值都是 double 计算、单机单次运行的结果，没有误差棒。
