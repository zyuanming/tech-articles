## 查证线

**这一篇的核心不是「浮点数不精确」，而是「哪个量级上加不进去」。** 审读时反复回到这一句：如果一段话不能落到某个具体量级或具体数字上，就删掉。

1. **2^53 那一节**：`float(2**53) + 1.0 == float(2**53)` 实跑为真；ulp = 2；连续加十次不动；加 2 才前进。这四个事实来自 `results.json` 的 `swallow`，自检里有两条断言盯着。
2. **3 项例子**：`[1, 1e16, −1e16]` 精确和 1、直接相加 0、Kahan 0、Neumaier 1——全部实跑。中间量逐步写进 `results.json` 的 `traces`，图 2 直接照抄，不另算。Kahan 第二行 c = 0 的原因（`t − s = 1e16 − 1` 在 ulp = 2 的量级上舍回 1e16）在正文与 `sources.md` 各写了一遍，两处口径一致。
3. **Fast2Sum 那句话**：初稿写成「`(t − s) − y` 等于这次加法的舍入误差」，复查符号时发现是**相反数**——Kahan 存负值，下一步 `y = x − c` 正好补回去。改了措辞，并把前提（|s| ≥ |y|）和失效方向（|y| > |s| 时 `t − s` 不再精确）写清。
4. **文献**：Kahan 1965（CACM 8(1):40，DOI `10.1145/363707.363723`）、Neumaier 1974（ZAMM 54(1):39–51，DOI `10.1002/zamm.19740540106`）、Dekker 1971（Numer. Math. 18:224–242，DOI `10.1007/BF01397083`）、Welford 1962（Technometrics 4(3):419–420，DOI `10.1080/00401706.1962.10490022`）、Shewchuk 1997（DCG 18(3):305–363，DOI `10.1007/PL00009321`）五条逐条过了 Crossref 的卷、期、页、年份。
5. **没读原文的边界**：Kahan 那篇与 Neumaier 那篇只核到元数据，没有读到全文。所以正文不写「他论证了……」「他指出……」，只写算法形式、标题、卷期页码，以及「通行的说法」「今天通行的变体」这种归因方式；`sources.md` 里也注明没有据此推公式。
6. **初稿把 Kahan 那篇写成「两页」**，Crossref 的页码是单页 40，标题「两页纸」也是错的，改成「一页纸和一篇修订」。
7. **`numpy.sum` 用两两相加、`math.fsum` 用 Shewchuk 无损变换**：前者是 NumPy 文档里写明的 pairwise，后者 CPython 文档与 Shewchuk 1997 都支撑。正文只拿来举例，没有宣称「因此 numpy 一定比 Kahan 准」。
8. **`-ffast-math` 那段**：写成「编译器被允许假设加法不产生舍入误差，于是算 c 的那一行成了可以删掉的死代码」，并明确「本文没有实测任何编译器」。不写成「实测开启后失效」。
9. **数值一致性普查**：正文出现的每个数都在 `results.json` 里能找到出处——1.776e−15 / 3.375e−14 / 9.237e−14 / 7.354e−13（`harmonic`）、4.796e−14 / 7.194e−13（`order`）、86.245% / 92.1% / 99.935% / 263 组（`cancel`）、8.97 / 433 / 2.6e−9 / 6.2e−9（`variance`）、1 / 4 / 5（`ops`）、两处 2^53 结论（`swallow`）、1e16 + 0.01（`representation`）。没有手写数字。

- **新增了「为什么 c 就是误差」一段**：初稿直接给出 Kahan 四行就跳到 Neumaier，读者会不知道 c 凭什么有效。补了 Fast2Sum 的前提与失效方向，这也是后面 3 项例子失败的原因——同一件事说两遍，但一遍是机理、一遍是实例。
