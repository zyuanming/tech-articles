# 一柜子齿轮，怎样提前画出明年的潮汐？

桌上没有盛海水的水箱，也没有一颗小月亮绕着小地球转。

只有转轴、齿轮、上下移动的架子，以及绕过许多滑轮的一条链。转动手柄，旁边的笔就能画出一条起伏曲线，供人编制潮汐表。

它凭什么知道海水明天几点涨、几年以后又怎样变化？

秘密不在于齿轮“懂得”海洋。秘密在于：人先把这个地点的潮汐写成若干条有规律的起伏，再让机器把这些起伏加起来。

![预测机把分量合成曲线的概念](assets/01-many-to-one.png)

这篇从一个旋转的小销钉出发，一路追到一条绳子的总长度。中途我们会手算一张小表，还会碰上一个有点反直觉的现象：两条简单曲线相加，原本看着像谷底的位置，竟然能冒出一个小峰。

## 2. “分潮”不是海里藏着几层水

先想一个跷跷板的端点：上去，下来，再上去。

只要它重复得够规律，就能用一条光滑的波线描述。潮汐分析里的“分潮”，可以先理解成这样一个数学上的起伏分量。

真实海水的运动受月球、太阳引力和海底地形共同影响。不同地点对这些周期性作用的响应各不相同，所以一个港口合适的振幅和相位，不能直接搬给另一个港口。

分潮不是说能从海里舀出一桶“月球水”和一桶“太阳水”。它是把一段复杂变化写成若干项的语言。

![分潮是可叠加的数学分量](assets/03-constituent-not-water.png)

这里其实有两件方向相反的任务：

- 分析：从一段实际水位记录里，估计出各分量的参数。
- 预测：参数给定之后，算出指定时刻各分量的值，再相加。

本文的齿轮机器主要干第二步。它不会凭空转几圈，就自己发现某个港口的全部参数。之前讲FFT时，重点是如何高效地分解信号；这次的重点，是如何把已经知道的分量，真的变成可以机械相加的位移。

![观测分析和预测是不同环节](assets/04-analysis-vs-synthesis.png)

## 3. 一个圆周运动，怎样变成上下起伏？

在圆盘上离中心一定距离的地方装一枚小销钉。圆盘匀速转动，销钉就绕着圆走。

现在只看销钉的高度，不管它左右移动了多少——你看到的就是一个周期性的上下运动。

![圆周运动的竖直投影](assets/05-circle-projection.png)

怎么让一个架子只跟着这个高度走？把销钉塞进一条水平槽里。销钉左右移动时在槽里滑，上下移动时带着整个槽架一起上下。槽架再被竖直导轨约束住。

这就是把“转动”变成“简谐运动”的一种销钉加槽架结构。下面是概念示意，不是第二号机的零件加工图。

![水平槽让销钉水平滑动而带动框架竖直移动](assets/06-pin-and-yoke.png)

把角度θ从圆的最高点起算。销钉离中心距离为A，那么它相对中心的高度就是：

q = A cos θ。

你不用先去背三角函数表。转到最高点，高度是A；转四分之一圈，高度是0；转半圈，高度是−A；再转回来，重复。

![一圈中的四个可手算位置](assets/07-four-positions.png)

## 4. 三个设置，各管一件事

一个起伏分量可以写成：

q(t) = A cos(ωt + φ)。

这三个符号都能落到看得见的机械动作上。

A是振幅，控制上下摆动有多大。销钉离盘心越远，行程就越大。

ω是角速度，控制一个周期要多久。不同的齿轮比让各根轴在同一个时间基准下转得快慢不同。

φ是初始相位，控制从圆周上的哪个位置开始。两只轮子大小一样、转速一样，只要初始角度错开，波峰就会错开。

![振幅频率相位三个控制量](assets/08-three-settings.png)

角度单位要统一。本文代码用弧度，所以一圈是2π。如果周期T用小时，ω=2π/T，单位就是每小时多少弧度。

“把某个波推迟3小时”和“加3弧度”完全不是一回事。推迟τ小时，就该把t换成t−τ，角度相应减少ωτ。相位必须连着时间原点一起理解。

![相位差对应时间平移](assets/09-phase-shift.png)

再看一张真实设置的照片。原档案把这一张说明为设置某个分潮的振幅与相位。照片里那个人的身份没有给出，我们也不替他编名字或者操作对白。

![设置分潮振幅和相位的NOAA原照片](assets/mach1d.gif)

## 5. 先不用机器，合成一个玩具潮汐

为了能手算，我们故意挑整齐的周期，不冒充任何港口的实际参数：

h(t) = 2 + cos(πt/6) + 0.5 cos(πt/3)。

t的单位是小时，h的单位在这个虚构例子里取米。平均基线2米，第一项振幅1米、周期12小时，第二项振幅0.5米、周期6小时。两项的初始相位都设成0。

![两条分量和基线](assets/10-two-toy-waves.png)

先算t=0：两只“轮子”都在最高处，结果是2+1+0.5=3.5米。

到t=3，第一项走了四分之一圈，贡献0；第二项走了半圈，贡献−0.5。结果是1.5米。

到t=6，第一项贡献−1，第二项已经绕完一整圈，贡献+0.5。结果还是1.5米。

![三个时刻的加法账单](assets/11-hand-sum.png)

高度相同，并不意味着处在相同的状态。t=3时曲线还在往下走，t=6附近却有一个小峰。我们后面再回来找它。

现在先记住预测机器在每个时刻要干的活：让各单元转到正确角度，读出各自的贡献，然后加起来。

## 6. 一条绳子，怎么做加法？

轮子能制造起伏了，还缺一个加法器。

设一根理想绳子不会伸长，始终绷紧。一端固定，绕过几个导向件，再从一个可以上下移动的滑轮下面穿过去，最后通到自由端。

如果活动滑轮往下移动1厘米，它左右两段竖直的绳子各变长1厘米，一共多需要2厘米。总绳长不变，所以自由端那一段必须缩短2厘米。

![一个动滑轮的两段绳长](assets/12-one-pulley.png)

这个2很关键。写成“滑轮移动多少，笔就移动多少”，比例立刻就错了。

把两个活动滑轮串进同一根绳子，用y1、y2表示它们向下的位置，z表示自由端向下的位置。在图中这个理想布置下，固定导向段和不变的绕轮弧长合起来记作C：

总绳长 L = C + 2y1 + 2y2 + z。

![双滑轮串联与自由端](assets/13-two-pulleys.png)

绳长固定，所以变化满足：

Δz = −2Δy1 − 2Δy2。

这已经是加法了。它带一个反号和一个2倍系数，我们用方向和刻度把它处理掉。

让每个滑轮相对自身基准向上移动q/2，也就是y=Y−q/2。这样自由端向下的增量，正好等于q1+q2。

如果还想让笔在纸上向上表示正数，再加一个固定转向连接或者反向标尺。机械位移的正方向，和纸上的高度正方向，是两套需要明确约定的东西——并非所有真实机器都采用本文这套布置。

![半幅输入消去两倍系数](assets/14-half-amplitude.png)

本文这张图是便于推导的绳长模型，省略了摩擦、绳的伸长、导向件厚度和张紧机构的细节。历史机器用过线、带或者求和链；不能据此把所有实物都说成同一根理想绳。

## 7. 两只滑轮一起动，答案仍能核对

继续用玩具例子。把长度单位按比例选好，设两个滑轮的基准位置都是10，自由端基准也是10。

t=0时，q1=1、q2=0.5，于是：

- y1=10−1/2=9.5；
- y2=10−0.5/2=9.75；
- z=10+1+0.5=11.5。

可变的那几段绳长加起来是2×9.5+2×9.75+11.5=50。

t=3时，q1=0、q2=−0.5，两个滑轮变成10和10.25，自由端是9.5。总长还是20+20.5+9.5=50。

![两个状态的绳长守恒账单](assets/15-length-ledger.png)

预测高度读作h=2+(z−10)。你会再次得到3.5和1.5。

机器并不需要先把这些小数写在纸上，再执行一条加法指令。绳长约束让自由端只能出现在符合加法关系的位置上。

![NOAA教材图1.2齿轮滑轮和记录笔](assets/source-noaa-2007-fig1-2.png)

## 8. 把时间轴一起带起来，才得到整条曲线

到这一步，自由端只告诉我们“此刻有多高”。要画出曲线，还得让纸按代表时间的比例移动。

一组齿轮把共同的输入轴分给各分潮轴，另一条传动路径推进记录纸。于是横向位置代表时间，纵向位置代表预测高度。

手柄转快些，表示在桌上更快地扫过预测时间，并不是让真实海洋加速。这也正是机器能提前算出未来的关键：参数来自已经分析过的观测，接下来只是把模型里的时间往前推。

![共同时间轴分到各单元并推进纸张](assets/16-common-time.png)

不过，手柄转得快并不自动等于精度高。传动间隙、链的伸长、摩擦、读数与设置误差，都会影响结果。我们没有操作或测量过这台历史机器，所以不能把数学图上的光滑曲线写成一次实际机械精度测试。

![误差来源从设置到记录](assets/17-mechanical-errors.png)

## 9. 为什么潮汐的节拍会慢慢“对上又错开”？

玩具例子里的12小时和6小时，纯粹是为了手算方便。真实世界里两个重要分潮M2与S2的周期却很接近：NOAA教材列M2约12.4206小时，S2为12小时。

两个节拍稍微不同的轮子，一开始对齐，以后逐渐错开，然后再重新对齐。

![接近的两个节拍逐渐错开](assets/18-nearby-periods.png)

用教材给出的角速度算：M2是28.9841042度/小时，S2是30度/小时。相对角速度就是两者相减，约1.0158958度/小时。

相对角度累积一整圈需要：

360 ÷ 1.0158958 ≈ 354.367小时，也就是14.7653天。

![相对转速决定再次对齐时间](assets/19-beat-period.png)

这是这两个分量相对相位的循环时间。它帮忙解释了：为什么它们的叠加会有一种较慢的强弱变化。

仍用振幅1和0.5做示意：两项同相时合成振幅是1.5，反相时是0.5。这里说的是两个分量的合成幅度，不是说“第14.7653天某港水位恰好1.5米”。实际各分潮的相位、其他分量、海湾的响应，还有天气，都还在场上。

![两分量合成的包络强弱](assets/20-envelope.png)

大潮、小潮确实和月日作用有关。但一个真实地方潮差最大的时刻，不能只靠一个两轮示意就断定它和某个月相瞬间完全重合。

## 10. 高潮时刻，为什么还要算另一条曲线？

画出h(t)是一件事，直接列出“几点几分高潮”又是另一件事。

一个光滑峰顶附近，曲线先升后降，最高处的变化率为0。于是可以另外合成各分量的变化率，再去找它们总和过零的位置。

![高度和变化率两条曲线](assets/21-height-and-rate.png)

如果一项是A cos(ωt+φ)，它的变化率就是−Aω sin(ωt+φ)。仍然是有规律的起伏，只是幅度多乘了ω，相位也变了。

NOAA对第二号机的说明，分别列出了高度求和与变化率求和，解释它怎样指示高低潮时刻。这个功能不能倒安到每一台早期机器身上：不同机器有的主要画曲线，有的专门指示高低潮。

还有一点要留心：变化率等于0本身，只给出候选点。一般的函数可能在平坦处继续上升，所以不能把每一个零点都不加判断地叫作峰或者谷。得看两侧的上升、下降有没有变号，才知道这里到底是什么。

![过零点需要检查两侧趋势](assets/22-stationary-is-candidate.png)

## 11. 回来找那个“谷里冒出的峰”

我们玩具例子的变化率是：

h′(t) = −(π/6) sin(πt/6) − (π/6) sin(πt/3)。

两项前面的系数相同，因为第二项振幅虽然减半，角速度却加倍了。

在t=4、6、8时，变化率都为0。直接算高度：

- t=4：2−0.5−0.25=1.25；
- t=6：2−1+0.5=1.5；
- t=8：又是1.25。

![四小时六小时八小时的局部峰谷](assets/23-small-peak.png)

所以t=6是夹在两处低谷中间的一个小峰。第一个分量正走到谷底，第二个分量却到了峰顶；两者的曲率一叠加，总曲线的局部形状就变了。

这说明一件事：不能先找出每条分量各自的高潮时刻，再取平均当作总高潮时刻。得先合成，再去研究合成后的曲线。

真实的读数装置长这样。档案说明它用来记录高低潮的时间与高度；我们不会从照片里模糊的纸面上编造一个港口或者某一年的真实数据。

![NOAA预测机记录时刻和高度原照片](assets/mach1e.gif)

## 12. 给齿轮正确参数，比把齿轮转起来更难

机器能执行一个模型，并不意味着这个模型自动就是对的。

港口的振幅与相位来自观测分析。记录太短、测量有误、时间基准混用，都会把错误带进设置里。把小时当分钟，或者混淆角度与弧度，更会得到一条漂亮但不对应原问题的曲线。

正式的潮汐预测还会处理天文论元和缓慢变化的校正。本文用固定的A、ω、φ，是为了看清合成机制，并没有把整套专业预测简化成三行万能公式。

![正确计算还需要正确参数与基准](assets/24-parameter-boundaries.png)

另外，实际水位也不只有可预测的天文潮。风、气压、河流都会改变水位。NOAA的现代水动力预报也会纳入一部分这类影响，和只做调和合成的潮汐表有不同的输入与预测范围。

所以，本文的玩具模型和配套代码不能用于航行、涉水、赶海或者任何安全判断。真要行动，请用当地主管部门的实时水位、天气、预警和适用的正式预报。

## 13. 用代码复算，再看滑轮真的怎样动

配套的[实验程序](examples/tide_machine_lab.py)只用Python标准库。最核心的高度计算很短：

```python
import math

def height(t, terms, mean=0):
    return mean + sum(
        amplitude * math.cos(speed * t + phase)
        for amplitude, speed, phase in terms
    )

terms = [(1, math.pi / 6, 0),
         (0.5, math.pi / 3, 0)]
print(height(0, terms, 2))  # 3.5
print(height(4, terms, 2))  # 1.25
```

程序实际做了6561组精确分数绳长检验，另外做了3200组随机合成与变化率核对、2880组圆周投影核对、3625组两分量包络核对。主要例子的三个驻点数值定位在4、6、8小时。

这些检验支持的是代码和理想模型之间的一致性，不是一次历史设备测量，也不是潮汐预测的准确率报告。

## 14. 真正值得记住的，是“一个约束替你做了运算”

圆周投影负责制造简谐运动。齿轮比负责节拍。销钉位置和初始角度负责振幅与相位。绳或链的总长度约束负责求和。记录纸把共同的时间变成横坐标。

这里面没有哪一步要求齿轮知道“海洋”这个词。机器准确地执行了人选择的数学表示；至于模型从哪里来、参数属于哪个地点、结果能信到什么程度，仍然要靠人的观测、分析和判断。

留一道拿纸笔就能做的题：如果把第二个分量的初始相位改成π，其他都不变，t=0时的高度是多少？

第二项从+0.5变成−0.5，所以结果是2+1−0.5=2.5。机械上相当于把第二个分量的起始角度翻转半圈，而不是把所有轮子的转速都改掉。

一柜子齿轮最有趣的地方，是它把一个看不见的“加号”，变成了你能沿着绳子逐段追踪的长度守恒。
