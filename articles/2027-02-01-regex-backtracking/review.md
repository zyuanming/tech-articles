- sha256 `e88f4e06e35b6fb6edc86285760073147ce70a053ed60e705a5ebf89fcd4c237`

审读方式：同一个 AI 助手写完初稿后重做一遍检查，独立性有限——它知道我原本想说什么，因此对「读者第一遍读会不会跟丢」的判断不如真正的陌生人可靠。凡是能用外部材料或重新跑一遍验证的，都做了；凡是只能靠人眼看的，见最后一节。

## 查证线

**1. 事故时间线与关键数字。** 抓取 Cloudflare 那篇复盘正文逐条对照：13:42 通过自动流程部署规则、13:45 自检开始失败、14:00 定位到 WAF、14:07 执行全局关停、14:09 流量与 CPU 恢复；原文写明「we had lost 80% of our traffic」与「went down for 27 minutes」。正文里「二十多个机房」「流量掉到两成」「27 分钟」都落在这几句话上。事故规则原文也逐字符比对过，图 18 的节选与原文的 `.*(?:.*=.*)))` 结尾一致。

**2. Cox 2007 的标题与论点。** 抓取 `swtch.com/~rsc/regexp/regexp1.html` 全文，确认标题里那串括号是原文自带的，确认「反向引用一进来就不是正则语言」与「`a?` 那组经典例子」都在原文中。正文没有把 Cox 的例子说成本文实测。

**3. Thompson 1968 的出处。** 用 Crossref 按 DOI `10.1145/363347.363387` 查元数据，核对刊名 CACM、卷期 11(6)、页码 419–422、日期 1968-06。此前误记过一个错误 DOI，查询结果显示那是另一篇（Matula, CACM 11(1): 47–50），已从正文与 `sources.md` 中剔除。

**4. 两份引擎文档的原话。** Go `regexp` 文档的「guaranteed to run in time linear in the size of the input」与 Rust `regex` 文档的「worst case O(m * n)」都是抓页面比对的，不是凭记忆转述。Rust 那页同时写了「lacks look-around and backreferences」，正好支撑正文「线性与反向引用不可兼得」那一段。

**5. 照片授权。** 图 15 用的是 1973 年 Thompson 与 Ritchie 的合影，来自 Wikimedia Commons，公有领域，原始来源 Jargon File。原件 310×201、19 590 字节，未缩放未重压缩。放弃 2019 年那批 CC BY-SA 照片的理由写进了 `sources.md`：公有领域没有署名与传播条件的负担。

**6. 正文每个数字回到 `results.json`。** 逐项对过：`catastrophic` 的十五个点（607 到 10 485 671）、`alternation`（1 235 到 327 595）、`cox`（78 到 163 838）、`cloudflare` 的 k 序列（18 到 848）与失配的 5 775、`rewrites` 的九个数、`linear` 的 256 倍与每字符 5.00 / 8.00、`anchor` 的 735 与 5 775、`pattern_size` 的 407 到 19 195、`memo_trace` 的 104 格 / 65 格 / 65 步。算错的不是文字，是初稿里有一句「惰性量词省了一半」——848 降到 49 明显不止一半，已改。

**7. 图与文的一致性。** 图 05 原本在注脚里引了「Cloudflare 博客用 Perl 调试器数出 555 步」。这个数字在本模型里跑不出来（口径不同），留着等于让读者拿两个不可比的数对照，已换成结构性表述。图 18 原本用的是自己缩写的规则片段，与原文比少了 `undefined|symbol|math` 与 `` |` `` 那几截，已改成忠实节选的五行。

**8. 引擎内部逻辑的对拍。** 新增第十组实验 `crosscheck`：15 个模式 × 121 个短文本（`{a, b, =}` 上长度 0–4 的全部串）× 3 个执行器，与 CPython `re.search` 逐个比对「匹配 / 不匹配」，5 445 次零分歧。这一组是我自己那套引擎的唯一外部锚点——它能说明三个执行器没有把「匹配成功」判错，但不能说明步数模型贴近真实引擎。

**9. 复现。** 在仓库外的临时目录里拷一份，删掉 `assets/`、`cover.png`、`results.json`、`figure-metadata.json` 与 `__pycache__`，重跑两个脚本：`results.json`、`figure-metadata.json`、`cover.png` 三份文件 `cmp` 逐字节一致，`assets/` 目录 `diff -r` 无差异。`run_model.py` 用时 2.5 秒，`build_figures.py` 5.2 秒。

## 没做的

- **没有目视看图。** 下面这条单独写。
- **没有用真实引擎验证绝对速度。** 这篇的步数是「执行了几条指令」，不是纳秒。正文已经写明这一点，但没有拿 Python、Perl、Go 实测同一输入的墙钟时间来佐证「形状一样」——那需要另一套基准，这一轮没做。
- **没有验证 RE2 与 RE2/J 是否真如文中所述。** 「RE2 卖点是不可信输入也安全」「Java 可以调 RE2/J」依据的是这两处的公开文档与 README 的通行说法，没有抓原始仓库核实版本与限制。
- **没有复核 Python 3.11 加原子组的发布说明原文。** 本机 3.14 上 `re.compile(r'(?>a+)b')` 与 `re.compile(r'a*+b')` 都能编译通过，这一步是实测；但「从 3.11 开始」这个版本号来自记忆，没有翻 changelog。
- **没有测 `linear` 组里回溯的 n=5 120。** 1 280 已经要 85 秒、10.5 亿步，再往后是小时量级。正文把这个断点写出来了，没有假装跑过。
- **没有审 `figkit.py`。** 它是同仓库其他篇目共用的画图工具，本篇只调用不改。它自己的断言（不出画布、不重叠、字号下限、调色板、对比度）这一轮没有重新验证。
