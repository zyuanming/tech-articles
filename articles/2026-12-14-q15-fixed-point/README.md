# # 一个 16 位小数能装下多少误差

把 0.1 存进 Q15 会发生什么，以及为什么四舍五入能换来 18 dB。

定点数最容易被讲成一句"精度低一点"。真跑起来不是这样：它会给你偏置、死区、消失的系数、抖不动的极点，每一样都有确定的数字。这篇文章从"0.1 怎么存"开始，一次讲一个坑：乘法怎么落位、偏置怎么攒成直流、加法溢出为什么翻符号、累加器为什么要 39 位、系数被量化之后低通为什么直接变没了、极点为什么只肯以 3 秒和 4.7 秒的间隔存在。

## 复现

```
python3 examples/run_model.py      # 生成 examples/results.json（约 0.3 秒）
python3 examples/build_figures.py  # 生成 assets/ 与 cover.png（约 5 秒）
```

`run_model.py` 只用标准库，自写了 xorshift32、三种舍入、饱和/回绕、极点与系数换算、正弦表与字长扫描。`build_figures.py` 需要 Pillow（3.14.7 / 12.3.0，见 `examples/run-environment.json`）。两个脚本都是确定性的，重跑得到逐字节相同的图。

## 关于数字

正文和图里的每个数字都由 `examples/q15.py` 算出。几个可以手算复核的：

- 0.1 × 32768 = 3276.8，四舍五入 3277，解码 0.1000061，误差 0.2 格。格宽 1/32768 = 0.0000305。
- 3277 × 3277 = 10738729；按 30 位小数解释是 327.72，落回 15 位要在 327 和 328 之间选。截断平均 −0.4966 格，四舍五入平均 +0.0002 格。
- 一个乘积 31 位；256 项之和最坏 256 × 1073741824 = 274877906944，39 位。int32 上限 2147483647，刚好是它的 1/128。
- 0.1 Hz 的截止系数 a = 1.3e-5，乘 32768 是 0.43，四舍五入变成 0——滤波器整个消失。
- T60 = 20 秒要求 r = 0.9999928，而 b1 = −r² 只有 −32768 一档可写，那是 r = 1、T60 = 无穷。

有一处结论是"负面"的，文章没有绕开：截断在端到端滤波里的信噪比只有 48.6 dB，比四舍五入低 18 dB——同一个算法、同样的位宽，差别只在那一条加法。这不是"精度低一点"，是差了三个比特。
