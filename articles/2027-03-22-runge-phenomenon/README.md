# 多给几个点，为什么反而更歪

1/(1 + 25x²) 在 [−1, 1] 上取 11 个等距点、用穿过它们的 10 次多项式去插值，最大偏差 1.92；取到 30 个点，偏差 334。这一篇从这个反例（Runge 1901）往回拆：三个点怎么就能差 0.62、误差为什么能写成「函数好不好逼近」乘「节点放大多少倍」、等距节点的放大倍数为什么是 2ⁿ 量级、切比雪夫节点为什么只按 log n 长、收敛率为什么被最近的极点钉死在 ρ = 1.22，以及换成切比雪夫节点也救不回来的 |x| 是怎么回事。

## 复现

```
python3 examples/run_model.py      # 生成 examples/results.json（约 0.9 秒）
python3 examples/build_figures.py  # 生成 assets/ 与 cover.png（约 3.2 秒）
```

两个脚本都是确定性的，重跑得到相同的数字与图（`results.json` 276 138 字节，md5 `7dadf4a0753dfe3d3f9e5df70039f44f`）。只需标准库（画图另需 Pillow）：求值是双精度的重心插值，不用 NumPy，不用任意精度——这里要看的正是「双精度够不够」。

`build_figures.py <N>` 可以只重画第 N 张，但那样会把 `examples/figure-metadata.json` 截断成一张，正式出图请整跑。

## 结构

| 路径 | 内容 |
| --- | --- |
| `read.md` | 正文，11 张图按出现顺序编号 |
| `assets/01..11-*` | 正文用图（1062 px 宽），与 `examples/figure-metadata.json` 一一对应 |
| `cover.png` | 1080×1080 封面 |
| `examples/interp.py` | 节点生成、重心插值、Lebesgue 常数、椭圆参数、收敛率拟合 |
| `examples/run_model.py` | 跑全部实验，写出 `results.json` |
| `examples/build_figures.py` | 画图，写出 `figure-metadata.json` |
| `examples/figkit.py` | 画图小工具（几何断言、字号换算） |

`interp.py` 的主要入口：

- `runge(x, a=25.0)` / `absx(x)`：两个被插值的函数，前者极点在 ±i/√a。
- `equispaced(n)` / `chebyshev(n)` / `chebyshev_lobatto(n)`：等距节点、第一类切比雪夫零点 cos((2i+1)π/2n)、含端点的 Lobatto 点 −cos(iπ/(n−1))。
- `bary_weights(nodes)` / `bary_eval(x, nodes, vals, w)`：重心形式的拉格朗日插值。求值不用显式的 L[i]，数值上也比直接求和稳。
- `interpolant(nodes, fn)`：返回一个 `x ↦ p(x)` 的闭包，节点上的值由 `fn` 给出。
- `grid(lo, hi, count)` / `sup_error(fn, nodes, count)`：均匀采样取 |f − p| 的最大值（正文所有「最大误差」都是这个量，默认 4001 点，扫表用 2001 点）。
- `lebesgue(nodes, count)`：用重心权重直接算 max Σ|L[i]|（不显式写 L[i]），同时返回取到最大值的位置。
- `basis_at(nodes, x)`：单个 x 上全部基函数的值，用来量每个 L[i] 的振幅。
- `ellipse_rho(imag, real=0)`：极点 z 对应的伯恩斯坦椭圆参数，取 z + √(z²−1) 的模。
- `fit_ratio(ns, errs)` / `fit_rho(ns, errs)`：对 log 误差与 n 做最小二乘，返回「每加一个点误差乘几」和它的倒数。
- `monomial_fit` / `vandermonde` / `solve` / `polyval`：给正文那个三点手算例子用的最小二乘与方程求根（列主元高斯消元）。

## 关于数字

正文里每个数都来自 `examples/results.json`，图也一样。数的是**插值误差、Lebesgue 常数与收敛率**，不是耗时。八处可以手算复核：

1. 三个点的抛物线：A = 1，C = 1/26 − 1 = −25/26 = −0.9615384615384616，`hand.coef` 逐位相同。x = 0.5 给 1 − (25/26)(1/4) = 0.7596153846153846，真值 1/7.25 = 0.13793103448275862，差 0.6217。
2. 节点间距：cos(π/22) = 0.9898214、cos(3π/22) = 0.9096320，差 0.0801894；中央 cos(9π/22) = 0.2817326，与 0 相距 0.2817326。比值 3.51，`nodes.cheb` 里是 0.080189 与 0.281733。
3. 椭圆的 ρ：极点在 ±0.2i，ρ = 0.2 + √(1 + 0.04) = 0.2 + 1.0198039 = 1.2198039；a = 1、a = 5 分别是 1 + √2 = 2.4142136 和 0.4472136 + √1.2 = 1.5426587。`rates` 里 `rho_theory` 给这三个数。
4. 拟合的 ρ：`fit_rho` 是 exp(−斜率)，实测 2.4142 / 1.5413 / 1.2180。与理论值的差（第三、四位）来自误差曲线的锯齿与最小二乘的取点范围，不是程序错。
5. Lebesgue 常数的 log 增长：切比雪夫节点有 λ_n ≈ (2/π)ln n + 0.9625，n = 30 给 3.1278，`sweep` 里是 3.128。
6. 到 10⁻⁶ 要多少点：a = 25 时 30 个点误差 0.005156，乘 0.82 的 k 次方到 10⁻⁶ 需 k = ln(5156)/ln(1/0.82) = 43.1，共 73 个点；a = 1 时 17 个点就到 10⁻⁶，`rates[0].rows` 里 n = 16 是 1.50e-6、n = 17 是 3.11e-7。
7. |x| 的慢：0.2706（n = 4）到 0.0334（n = 30），端点比值开 26 次方是 0.923，最小二乘给 0.9317（差在锯齿）；正文取「每加一点乘 0.93」。按 0.93 算，掉两个数量级要再 63 个点，正文写「六十多个」。
8. 网格分辨率够不够：`lebesgue` 在 2001 点上量到的值与 40001 点上逐位相同（例如 n = 30 都是 3.448e6，峰值在 x = ±0.984），说明这些数不是被采样网格截出来的。

模型没做的事：没有用任意精度重算（双精度就是讨论对象）、没有比较最小二乘/样条/有理逼近等其他重建方式、没有做二维或三角网格上的对应实验、没有测实际绘图库（numpy 的 `Chebyshev.fit`）的行为、没有把 |x| 的最优逼近与切比雪夫插值分开量、没有做到 n > 30（等距在 n = 29 已经到 1130，再往上双精度的消去误差会开始说话）。`sources.md` 里逐条写明哪些是文献、哪些没做。
