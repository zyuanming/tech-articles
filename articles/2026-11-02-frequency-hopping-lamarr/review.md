## 改了什么（一类）

**33 处半角双引号改成「」。** 这篇的引号最密：从第一节船上的「世界上最美丽的女人」到第十六节「Wi-Fi 之母」这个说法的拆解，几乎是每节一两处。替换脚本对同一行里出现第二对引号时会写成『』（它按嵌套处理），这里全部回退成「」——那十处其实是并列的两个引语（「做得足够准」／「不准就拉回来」、「跳多快」／「它反应多快」），不是嵌套。改完 46 对「」、成对闭合，代码块和行内代码没有被动过。

## 核对过但没改的

这篇的数字密度是全库最高的之一，抽了十五处复算，全部与 `examples/results.json` 一致：

- 频点数三档：4 路 6.02 dB / 40×，7 路 8.45 dB / 70×，88 路 19.44 dB / 880×——`channel_counts` 三行；7 与 88 的差 10.99 dB 也由 19.44 − 8.45 得出。
- J/S = P / (f × 88)：f = 1/88 → 30（打穿）、f = 0.2 → 1.70、f = 1 → 0.34；P = 30 换成 dB 是 14.8。
- 部分频带打断率：18/88 = 20.5% 的几何值，四千跳实测 21.4%（`parked.share`），两百跳 38 次 = 19%——`waterfall_parked` 前 200 行里 `true` 正好 38 个，图和正文说的「这张图自己的数」对得上。
- 序列：88 个频点全用到、χ² 85.4（自由度 87）、与上一跳相同 51 次（期望 45.45）、最少 34 次最多 72 次、均值 45.45——`sequence` 六个字段。
- 功率表七行：10 / 880 / 176 / 20 / 880 / 10 / 10 倍，对应打断率 100 / 100 / 21.4 / 2.4 / 100 / 100 / 0%——`compare` 逐行；扫频那行 `per` = 0.0243，正文写 2.4%。
- 反应时间曲线：0.5T 时 50.4%（正文「只有一半」）、0.8T 时 12%、1.0T 起为 0——`reaction` 九行。
- 跳速表七行：100 / 20 / 4.17 / 2 / 1 / 0.5 / 0.2 ms 与 d/T 0.02 / 0.1 / 0.48 / 1 / 2 / 4 / 10——`rates`；「分界在 250～500 跳/秒之间」与 0.48、1.00 这两个比值一致。
- 失步：慢 0 跳 100%、慢 1 跳 1.27%、慢 2 跳 1.12%、慢 3 跳 1.15%——`sync`；「剩下那 1% 是巧合」= 1/88 = 1.14%，落在实测的 1.1–1.3% 中间。
- 处理增益 10·log₁₀88 = 19.44 dB、「88 倍功率」：`gain` 19.44，`gain_curve` 的 2/4/8 行也确实是 3.01 / 6.02 / 9.03 dB。
- 发条电机「千分之一精度、一分钟漂几十毫秒」：1e-3 × 60 s = 60 ms，和后半句自洽；「每秒 100 跳、一跳 10 ms，半分钟漂掉一整跳」= 30 ms 的漂移对上 10 ms 的跳长。
- 三档现实系统（GSM 217、SINCGARS ~100、蓝牙经典 1600 跳/秒）没有改动：这是公开规格的量级描述，与前文 250–500 跳/秒的分界线不冲突。
