# # 一条光线，459 次白问

每个像素都要发一条光线进场景，问它先撞上了什么。最直接的办法是挨个问：464 个图元，就测 464 次——其中 459 次白问。

这篇文章讲怎么把这堆白问省掉：先把东西装进盒子，盒子再套盒子，问一次盒子就能扔掉一整个分支。这也是 BVH（包围体层次）的全部内容。

场景是一个能真的渲染出图的光线追踪器：320 个球排成环形隧道，144 块地板砖，Whitted 风格的阴影与镜面反射，4 倍超采样抗锯齿。三种建法（中位数切、空间等分、SAH）在同一条场景、同一批光线上对比，数字全部来自 `examples/`。

## 复现

```
python3 examples/run_model.py      # 生成 examples/results.json（约 27 秒）
python3 examples/build_figures.py  # 生成 assets/ 与 cover.png（约 20 秒）
```

`bvh.py` 与 `run_model.py` 只用标准库（向量、球与平面的求交、三种建树、遍历计数、Whitted 渲染）。`build_figures.py` 需要 Pillow（3.14.7 / 12.3.0，见 `examples/run-environment.json`）。两个脚本都是确定性的，重跑得到逐字节相同的图。

`build_figures.py` 不读中间文件，它自己重渲染 160×90 那一帧和 320×180 那张大图，并断言像素数据的 `sha256` 与 `results.json` 里记的一致——这也顺带证明了「BVH 和朴素遍历的图逐字节相同」。

## 关于数字

正文和图里的每个数字都由 `bvh.py` 与 `run_model.py` 算出（`results.json` 129 KB，其中 14400 个热力图数值占了大头）。几个可以手算复核的：

- 朴素遍历的求交次数 = 光线数 × 图元数，`run_model.py` 里有一条断言守着它。160×90 那一帧是 25 495 × 464 = 11 829 680。
- 92.6 倍 = 464.0 ÷ 5.0127。同一帧、同一批光线的总求交次数之比。
- SAH 曲线最低点：代价 276 237 = 左盒表面积 × 222 + 右盒表面积 × 242，222 + 242 = 464，正好是根节点的全部图元；最贵的 11 号切点是 404 073，比最低点高 46%。
- 两处口径不同，正文里都标了：热力图的 3.92 次是 14 400 条纯主光线的平均；5.01 次是 25 495 条（含阴影线与反射线）的平均。
- 「地板是无限平面」的对照实验里，无限平面版本只有 321 个图元，每条光线却要 4.22 次求交，比 464 个图元的砖地版本（3.95 次）还多——图元少反而更慢，因为那块平面的包围盒有 2000 公里见方，把树的第一层废掉了。
- 建树的比较次数只在同一种切法内部有意义：中位数切 18960 次、空间等分 3551 次、SAH 1672 次，但「一次排序比较」和「一次 SAH 估价」不是同一种操作，这三个数不能直接相减。

一处值得单说的结论：**「先走靠近的那个孩子」几乎没有收益**。同一棵树、同一批 3600 条光线，正常遍历 14 211 次求交，先远后近 14 916 次，只差 5%；而关掉距离剪枝会涨到 26 083 次，多 84%。真正干活的是剪枝，不是顺序。

`sources.md` 里写明了文字参考、那张照片的许可、每张图的数字来源、模型的简化假设，以及明确没做的事（没有 SIMD、没有 GPU、没有打包遍历、没有目视看图）。
