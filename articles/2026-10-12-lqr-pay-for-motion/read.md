# 既想快点回家，又不想每一步动太猛，机器怎样做取舍？

假设一个游戏角色站在目标右边4格。你可以给它一条指令：下一拍向左或向右移动多少格。

猛地向左移动4格，马上到家。可如果大动作要扣分呢？一动不动倒是省动作，离目标却一直很远。

我们给这一步写两张账单：下一拍离目标的距离平方，加上本次移动量的平方。

- 不动：距离4，动作0，扣分16。
- 一口气左移4格：距离0，动作4，扣分也为16。
- 只左移2格：距离2，动作2，总分4+4=8。

两种看起来很干脆的极端选择，居然都输给了中间方案。

![同一状态下，不动、一步到位、移动一半的两项成本比较](assets/01-three-choices.png)

这篇文章要追的，就是这个问题：**如果还剩好几步，怎样既顾眼前、又顾后面，从取舍规则里算出一套控制动作？**

答案之一叫LQR，Linear Quadratic Regulator，线性二次调节器。先别急着背名字。我们会从一条数轴和几个平方开始，亲手倒推出它为什么是一条反馈规则。

## 1. 先把这个小世界说清楚

把目标放在0。角色在右边，位置误差x为正；在左边，x为负。指令u为正表示右移，为负表示左移。

每一拍的模型是：

**下一拍的误差 = 这一拍的误差 + 这一拍的移动指令。**

写成短式：x(k+1)=x(k)+u(k)。k只是第几拍的编号。

![一条数轴上的目标、当前误差4和向左移动的负指令](assets/02-state-command.png)

一格是我们选的参考长度；x和u都是用这个长度归一化后的数值。u是“这一拍想移动多少格”，不是电机的力，也不是加速度。模型假定指令能在这一拍完成，没有惯性、障碍物和速度限制。

真实小车当然复杂得多。先把这些困难放在门外，不是说它们不重要，而是为了单独看清“取舍怎样变成公式”。这里所有轨迹都来自教学模型，不是实车实验。

如果你读过前面的可控性，小车那里用位置和速度两项状态、用加速度作输入；本篇这一维模型是另一个明确简化的系统，不能把两篇的输入单位混着用。

## 2. 为什么要平方？谁决定扣多少分？

平方有几个方便的性质。

向左偏2格和向右偏2格，都扣4分；偏4格要扣16分，比偏2格严重得多。大动作也会被更重地记账。曲线平滑，之后容易找到最低点。

![误差平方与动作平方是两类不同账单，正负方向都计入代价](assets/03-two-bills.png)

但平方不是自然界颁布的唯一评分标准。你也可以关心最大误差、总路程、动作变化率，或绝对不能碰到的墙。那会得到不同的优化问题。

我们先用两个非负权重q、r来决定在意程度：

**这一拍的成本 = q×x的平方 + r×u的平方。**

q越大，偏离目标越贵；r越大，动作幅度越贵。这里取r严格大于0，使任何非零动作都付出成本；q可以为0。终点还可以另加一张账单，稍后介绍。

这些分数是设计者写下的偏好，不自动等于焦耳、电费或电机损耗。若把位置、速度、电流等不同单位混到真实模型里，权重还必须配合单位和参考尺度。仅把米改成厘米，却不相应改权重，可能把同一物理问题改成另一份评分。

![一个平方成本盆地，说明选择规则存在中间最低点](assets/04-one-step-bowl.png)

开头那道题，可以不用微积分解。

下一拍误差是4+u，未来误差与动作的账单为：

(4+u)²+u² = 2(u+2)²+8。

平方不能小于0。因此u=−2时，最低成本恰好是8。你看，最优并不是“感觉折中一点”，而是相对于这张明确账单，找到了可以证明的最低点。

## 3. 一篇老论文提醒我们：先说清“最优”指什么

1960年，Rudolf E. Kálmán的《Contributions to the Theory of Optimal Control》研究线性系统的二次型调节问题，把状态描述、可控性、可观性、Riccati方程以及存在性、稳定性条件连在一起。[原论文](https://liberzon.csl.illinois.edu/teaching/kalman_paper.pdf)

![Rudolf E. Kálmán的ETH机构档案原照片](assets/05-kalman-eth-original.jpg)

*照片：ETH-Bibliothek Zürich，Bildarchiv；摄影者未知；HK_04-01925，2007-12-27；CC BY-SA 4.0。原图未修改，完整署名、来源和许可见[sources.md](sources.md)。这不是1960年写论文时的照片。*

有意思的是，原论文在研究最优反馈之后，专门指出：不能悄悄假定一个系统只要使用最优控制，就必然稳定；需要继续检查成立条件。这句话比“算法会自动选出最好的一切”谨慎得多，也重要得多。

Kálmán在署于1978年的回顾中，把这项工作描述为多种思想的结合；该回顾于1979年刊出。我们不把这段发展史压成“某天突然想出一个万能系数”，也不把连续时间原论文的符号直接当成下面的离散两步算例。[作者本人回顾](https://garfield.library.upenn.edu/classics1979/A1979HE37100001.pdf)

![到得了、按账单最省、长期稳定是三个相关但不同的问题](assets/06-three-questions.png)

我们这一篇只先解决一个边界清楚的问题：模型已知，状态已知，还剩有限步，输入暂无限幅，给定二次成本，怎样使总成本最低？

## 4. 还有两步时，不能只算这一步

现在回到x=4的角色，让它移动两次。分别记作u0、u1，状态依次是x0、x1、x2。

- x0=4，是已知的起点。
- x1=x0+u0，是第一步之后。
- x2=x1+u1，是第二步之后。

选择q=r=1，终点权重也取1。总成本规定为：

**J = x0²+u0² + x1²+u1² + x2²。**

![两次动作与三次状态记账，终点只记误差没有第三次动作](assets/07-two-step-timeline.png)

这条式子每一项都有位置：开始时的误差、第一次动作、中途的误差、第二次动作、最后的误差。

x0²已经确定，怎么选动作都要付；它不会影响最优选择，但算总账时仍在。x1、x2却会被前面的动作改变，不能当作互不相关的数字。

最常见的偷懒办法，是只看眼前的x0²+u0²。因为x0已经固定，最省的u0就是0。下一拍再这样想，又是0。角色当然永远不回家。

关键不是“多做几次局部最小化”，而是把每一步对后面的影响算进去。

## 5. 先假装已经走到最后一步

从最后一步倒着想，事情反而简单。

假设第一步已经走完，当前误差是某个数x。我们还可以选一次u，然后结束。剩余账单是：

x²+u²+(x+u)²。

整理成平方：

**x²+u²+(x+u)² = 2(u+x/2)² + (3/2)x²。**

![最后一步把成本配方，最低点是u等于负x的一半](assets/08-last-step-square.png)

因此，不管最后一步开始时x是多少：

- 最合算的动作是u=−x/2。
- 从这里走到结束，最低还要付(3/2)x²。

第二条和第一条一样重要。它把“后面还有一个需要选择的动作”压成了一张简单价目表。

当前x=2，最少付6；x=4，最少付24；x=−2，仍最少付6。

![剩余最低成本为1.5乘以误差平方，不同误差沿同一张价目表取值](assets/09-cost-to-go.png)

我们把这张“从当前状态起，后面都选好时最低还要付多少”的表叫价值函数，或最小剩余成本。这里记为V1(x)=(3/2)x²。

它不是随意猜未来，也不是把未来省略。它是已经把最后一步优化过之后，交给前一步的精确摘要。

## 6. 带着这张价目表，退回第一步

第一步选u0后，角色会落在x1=4+u0。

既然后面最少要付V1(x1)=(3/2)x1²，第一步只需最小化：

16 + u0² + (3/2)(4+u0)²。

再配一次方：

**16+u0²+(3/2)(4+u0)² = (5/2)(u0+12/5)² + 128/5。**

![第一步不是重复一半规则，而是把后面的最低成本一起计算](assets/10-first-step-square.png)

最低点出现在u0=−12/5，也就是−2.4。

于是：

- 第一步左移2.4，x1=1.6。
- 最后一步按刚才求出的规则，左移x1的一半，也就是0.8。
- 最后x2=0.8，总成本25.6。

![两步最优轨迹从4到1.6再到0.8，并逐项核对成本25.6](assets/11-optimal-two-steps.png)

你可以亲手核账：

16+5.76+2.56+0.64+0.64=25.6。

如果第一步就左移4格，后面不动，总成本是32。若两步都不动，总成本是48。最优方案没有最快到达0，却在这份评分里赢了。

这也回答了一个很容易误解的问题：**有限步LQR的终点罚分，通常是软要求，不是“必须精确到达0”的硬约束。** 终点还有0.8，不是程序漏算。若任务明确要求第二步必须到0，那应该把这个要求放进问题，而不是事后责怪原算法没有读心。

![软终点罚分与必须精确到零的硬约束对照](assets/12-soft-endpoint.png)

## 7. 倒着算成本，正着用反馈

刚才写出的−2.4、−0.8，可以当作一份从x0=4出发的行动表。

但倒推过程给出的东西更有用：它不是只为4算了一次。

如果第一步开始时误差是任意x，把4换成x，同样配方，就得到：

- 第一步：u=−(3/5)x。
- 最后一步：u=−(1/2)x。

![两条增益按剩余时间选用，动作按当时实际状态生成](assets/13-feedback-rules.png)

这里的系数叫反馈增益。它把当前状态变成当前指令。负号意味着往减少误差的方向走；系数决定这次纠偏有多大。

所以，我们可以先离线算好“还剩两步用3/5，还剩一步用1/2”，运行时再读当时的状态，乘出动作。**倒推是在计算未来的价目表；实际运动仍按时间向前发生。**

同一条标量规则看起来很像比例控制，但这里系数来自模型、剩余时间和整段成本。它不意味着一般多状态LQR就是只看位置的单一比例按钮。

## 8. 如果中途被推了一下，行动表和反馈有什么不同？

仍按原计划走第一步：u0=−2.4，本来应该到x1=1.6。

假设这一拍结束时发生了一次额外的+1偏移，实际到了2.6。这个偏移不是此前优化时已知的条件，是我们另设的教学扰动。

照抄旧行动表，第二步仍走−0.8，最后剩1.8。

按反馈规则，最后一步先读实际x=2.6，再走−1.3，最后剩1.3。

![同一中途扰动后，预先写死的第二步与按实际误差调整的第二步](assets/14-disturbance.png)

在实际x1=2.6已经发生、且最后一步模型仍准确的条件下，反馈选择把剩余成本压到了最低：

- 旧指令：2.6²+0.8²+1.8²=10.64。
- 反馈指令：2.6²+1.3²+1.3²=10.14。

差别不大，却说明反馈的本质：不是宣称世界绝不会偏离计划，而是根据新的当前状态作出选择。

这不等于我们证明了“任意随机扰动下，整段过程仍有原来的最优性”。带噪声的模型、状态估计误差、对未来扰动的假设，都是另外需要写清楚的条件。

![模型、当前状态和成本各自提供的信息，不能互相代替](assets/15-feedback-information.png)

## 9. 把两步的规律压成一条递推

现在才给这一过程起更正式的名字。

当状态转移是线性的、代价由平方或二次型组成，并希望把状态调节到目标附近时，就到了LQR的世界。

先保持我们最简单的x(k+1)=x(k)+u(k)，只把权重换成q、r。假设下一拍之后最低还要付p_next×x_next²。那么当前要选u，使下面的式子最小：

q×x² + r×u² + p_next×(x+u)²。

配方得到两条规则：

**反馈增益 K = p_next / (r+p_next)，动作u=−Kx。**

**当前剩余成本系数 p = q + r×p_next / (r+p_next)。**

![下一步系数进入递推，产生当前增益和当前成本系数](assets/16-recursion.png)

为什么只需传一个p？因为优化之前是二次式，优化之后仍然是“一个系数乘x²”。整张价目表的形状没有变，换的只是弯曲程度。

从终点开始，令p等于终点罚分权重qf，再向前倒推。我们取q=r=qf=1时：

终点p2=1 → 最后一步p1=3/2 → 第一步p0=8/5。

算动作时用的是**下一时刻**的p。最后一步的K1=1/(1+1)=1/2；第一步的K0=(3/2)/(1+3/2)=3/5。这里的下标错一位，结果就变了。

![成本系数从后向前走，状态和指令从前向后走](assets/17-backward-forward.png)

在更一般的线性系统里，状态可以是一列数，p会变成矩阵。这一族递推称为离散Riccati递推。名字不必先记牢；先记住我们刚刚完成的动作：**用后面的最小剩余成本，把当前选择变成一个可以直接求最低点的二次式。**

## 10. 调权重，究竟改了什么？

保持同一个x0=4、两步时长、q=qf=1，只调整动作权重r。实际精确分数程序算出：

- r=1/4：第一步约−3.310，最后误差约0.138。
- r=1：第一步−2.4，最后误差0.8。
- r=4：第一步约−1.241，最后误差约2.207。

![同一起点与时长下，三个动作权重产生三种不同轨迹](assets/18-weight-trajectories.png)

动作越来越贵，控制器就愿意留下更大的位置误差，以少动一点。

但不要拿三份加权总成本直接排名，说哪个r对应的数字最小、所以哪套控制最好。换r就是换评分表，跨评分表比较总分很容易误导。可以分别看未加权的位置误差平方和、动作平方和，再判断哪个取舍符合任务。

![把误差成本和动作成本分开看，避免拿不同评分表的总分比较](assets/19-tradeoff-ledger.png)

另一个小性质：若把q、r、qf都乘以同一个正数，比如同时乘100，每个候选方案的总分都乘100，名次不会变，反馈增益也不会变。重要的是相对权重，而不是把所有数写得更大。

## 11. 动作罚得很贵，能保证不超过上限吗？

不能。

刚才r=4时，第一步系数是9/29。若起点不是4而是40，第一步指令就是−360/29，约−12.41。r还是4，动作却已经很大。

![同一个高动作权重下，把误差放大十倍仍会把指令放大十倍](assets/20-soft-not-cap.png)

因为这套无约束公式u=−Kx是线性的：状态放大十倍，指令也放大十倍。

“每步最多移动1格”是硬约束，不是“动作很贵”的同义句。你可以在输出端把指令裁到[−1,1]，但裁过之后，就不能原封不动套用无约束LQR的最优性证明。

![未限幅的两步轨迹和每步裁到一格后的实际轨迹](assets/21-clipped-model.png)

本稿把x0=4、原增益的输出裁到±1后，得到4→3→2，成本31。原无约束方案的25.6已经不是这条限幅轨迹的成本。

这个例子只证明“加入上限改变了动作与问题”，不声称裁切在所有受约束问题里必然差于最优；有些简单特例可能碰巧相同。想系统处理墙、速度和输入上限，需要把约束放进优化过程，后面的MPC篇会继续这个问题。

## 12. 为什么“最优”仍然不自动等于“稳定”

让我们故意写一张很糟的评分表。这类反例也出现在[Boyd的归档无限时域课件第11页](https://ee363.stanford.edu/archive/lectures/dlqr-ss.pdf)。

换一个会自行放大误差的系统：x(k+1)=2x(k)+u(k)。设动作要扣平方分，但误差完全不扣分：q=0、qf=0、r=1。

最省动作的策略当然是u=0。成本为0，已经不可能更低。可是从x0=1出发，状态却是1、2、4、8、16、32……

![误差完全不计入目标时，零动作可以最优而状态不断增大](assets/22-optimal-not-stable.png)

算法没有违反评分表，是评分表根本不在乎你最担心的事。

有限时间里“按这张表最省”，与无限时间里“状态回到目标”，是不同命题。无限时域LQR的稳定结论需要相应条件。上面课件给出的一组充分条件是：系统可控，成本所关注的状态信息又具有相应的可观性。直观上，不稳定的方向必须有办法管住，也不能在评分里彻底隐身。这里不省掉这些条件，也不拿两步计算代替一般稳定性定理。

还有其他边界：状态得能取得或估计；模型若漏掉了延迟、饱和和重要动力学，纸上最优未必是现实里合适的控制。平方惩罚u也不等于惩罚相邻两次指令的变化u(k)−u(k−1)；如果你在意动作忽快忽慢，应当把那个要求单独建模。

## 13. 一个小彩蛋：这个极简模型里会出现黄金比例

仍用x_next=x+u、q=r=1。把时长延得很远，远离终点的递推系数逐渐接近固定值p。

固定值意味着再递推一次还是它自己：

p = 1 + p/(1+p)。

两边整理，得到p²−p−1=0。取正根：

p=(1+√5)/2，约1.618。

反馈增益K=p/(1+p)，约0.618；每一步剩余误差约乘0.382。

![本模型的成本系数递推接近1.618，反馈增益接近0.618](assets/23-golden-limit.png)

这不是“自然界的最佳控制比例永远是黄金比例”。只因我们特意选了a=b=q=r=1，固定点方程恰好变成这一条。改一下动作代价，数字就变了。

这也是学习算法很有趣的地方：一个看似熟悉的常数，会从另一条路出现；理解它出现的条件，比把它当成万能口号更有用。

## 14. 把整个两步例子亲手跑一遍

下面这段代码只做我们刚才的精确分数计算，不依赖控制库。

```python
from fractions import Fraction as F

p = [F(0), F(0), F(1)]
gain = [F(0), F(0)]
for k in range(1, -1, -1):
    gain[k] = p[k + 1] / (1 + p[k + 1])
    p[k] = 1 + p[k + 1] / (1 + p[k + 1])

x = F(4)
for k in range(2):
    u = -gain[k] * x
    x = x + u
    print(k, u, x)
```

它依次打印：第一步指令−12/5、到达8/5；第二步指令−4/5、到达4/5。

![两次实际分数输出，和前面的手算轨迹一一对应](assets/24-code-results.png)

[完整实验程序](examples/lqr_lab.py)还实现了更一般的标量x_next=a×x+b×u，并且用另一条路线核对答案：把所有时刻的状态展开为整段动作的函数，直接建立二次目标的线性方程组，用精确分数消元。它与倒推算法没有共用Riccati递推来制造“相互验证”。

实际检查了1620组时长、模型与权重组合；另有3000组任意动作序列，用配方恒等式核对它们比最优多付的成本，随机种子196001。两步动作网格的961组候选也找到了同一个最低点。再加上扰动、限幅、反例与权重同比缩放测试，范围都写在[实验说明](examples/README.md)。

![递推、整段二次优化和非最优序列的平方余量三种核验视角](assets/25-checks.png)

这些是已运行的精确模型计算，没有测量真实机器的能耗、控制时延或安全性能。

把时长另外改成12步，仍从4出发，下面三条轨道分别使用r=1/4、1、4的反馈。动画13帧对应k=0到12的实际计算状态；它只显示每拍的位置，没有假装知道两拍之间的真实运动。这个新时长明确不同于前面的两步手算。

![十二步时长下三种动作权重的实际状态序列动画](assets/26-weight-motion.gif)

最后试一个小练习：开头只有一步，若把动作平方前的权重改成3，下一拍误差平方仍取1，x=4，该走多少？

配方或套一小步公式都可以：u=−4/(3+1)=−1。误差还剩3，未来误差成本9，动作成本3，总共12。想让它动得更少，正是这张新评分表的选择。

LQR没有替人决定什么值得追求。它做的是：**把你写下的模型和取舍，推到底，变成每一步能够执行的反馈规则。**

而你仍要问：这份模型像不像对象？这张账单在不在乎真正重要的东西？那些绝不能违反的边界，有没有被认真写进去？
