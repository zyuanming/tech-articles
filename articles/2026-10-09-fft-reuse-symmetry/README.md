# 一百万次计算，怎样变成五千次？FFT 没有删掉任何声音

正文：[read.md](read.md)。本文用一个四点例子把蝶形拼接走完，再把 radix-2 的工作量算到 1024 点，说明“快”来自不重复劳动，而不是丢掉微弱成分或降低精度。文中的实现是最小教学版本，不是任何库的复刻。

## 环境与运行

本次 Python 3.15.2，只用 `cmath`、`json`、`math`、`platform`。脚本不联网、不下载、不安装。

在本文目录执行，输出目录须为空或不存在：

```sh
python3 examples/butterfly.py --out ./my-results
```

输出 `results.json`，与本次 [expected-results.json](examples/expected-results.json) 核对。脚本会断言四点例子、8 点与 1024 点的乘法计数，失败即退出。

## 数值口径

- 四点例子：偶数组 `1、3` 的 DFT 是 `[4，−2]`，奇数组 `2、4` 是 `[6，−2]`，k=1 的权重 W=−i，拼接得 `[10，−2＋2i，−2，−2−2i]`。
- 递归实现在 `[1..8]` 上与逐项公式的最大偏差 < 1e-9；复数是浮点，末位不保证与另一种计算顺序逐位一致。
- 计数口径：直接公式 `1024×1024＝1,048,576` 个乘法项；基础蝶形 `(1024/2)×10＝5120` 次复数乘法、`1024×10＝10240` 次加减法。计数脚本在 N=1024 上真的数出 5120。
- “百万变五千”是乘法项数之比，不是秒表测出的加速比；内存访问、向量化与函数开销都会改变实际速度。
- 没有给出“乘数是 1、−1 或 ±i 的平凡乘法占多少”的统计，本文只说还能进一步简化。
