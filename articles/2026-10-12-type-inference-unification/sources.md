## 一手事实及使用范围

1. **Luis Damas、Robin Milner，Principal type-schemes for functional programs，POPL 1982，207–212。** [ACM正式记录](https://doi.org/10.1145/582153.582176)；[课程存档中的原论文](https://www.cs.tufts.edu/comp/150FP/archive/robin-milner/damas-milner-original.pdf)。实际查看原扫描六页：207页说明ML最初是LCF的元语言及最一般类型问题；208页给出主类型方案和核心语法；209页给出推导规则与概括的环境侧条件；210页给出实例化推导、统一及闭包定义；211页给出W及可靠性/完备性陈述；212页核参考文献。论文说明更详细证明将见第一作者博士论文，本文不声称这六页含有全部证明细节。本文的 twice、两种绑定比较、捕获类型错误与组合管道按这些规则自设演示，不是逐段翻译论文。
2. **R. Hindley，The Principal Type-Scheme of an Object in Combinatory Logic，Transactions of the AMS 146，1969年12月，29–60。** [正式DOI](https://doi.org/10.1090/S0002-9947-1969-0253905-6)；[原论文扫描](https://www.cs.tufts.edu/~nr/cs257/archive/roger-hindley/principal-type-scheme.pdf)。实际读29–32页文本并查看29、30页原扫描：身份算子与类型方案、主类型的实例含义、结果范围，以及30页关于Curry独立证明和协助的作者说明。没有把这篇组合逻辑论文说成已经给出现代ML的let语法，也没有声称通读和重证全部32页。

正文中的“秩一”只用于限定本文类型方案所在的位置：我们没有把带forall的任意多态方案直接作为函数参数类型。`a -> a`的两个a必须一致；参数绑定的单一类型与let绑定的可实例化方案不同。本文没有子类型、隐式转换、重载、递归类型、可变引用、异常或一般递归。

## 实验的输入、结果与边界

[infer_lab.py](examples/infer_lab.py) 使用不可变类型结构、显式替换与Algorithm W路线；[check_lab.py](examples/check_lab.py) 另写可变类型图、破坏式连接与工作列表统一，再比较两者输出。均只依赖Python标准库；实际运行环境Python 3.12.14。直接运行前者看具名例子，运行后者看检查结果。

作者实际执行：

- 10个具名案例，包含 identity、twice、compose、let两类型使用、参数两类型冲突、共享外层返回值、错误概括反例、`fun x -> x x`拒绝、`let id ... in id id`通过、整数加法与Bool冲突。
- 枚举所有AST节点数1至9的闭合纯lambda项，共 **2622** 个。每个变量、函数定义、调用各计一个节点；仅包含这三种构造，不含let、字面量或二元组。变量名按绑定层级规范化；两实现均接受其中1750个，并在每项的接受/拒绝和接受时的规范化类型上完全一致。
- 固定随机种子 **20261012**，生成20000棵深度至多6的小语法树，含Int/Bool、固定类型add/not、变量、函数、调用、let、同名遮蔽和二元组。两实现均接受10436棵，全部20000棵的结果一致。随机树可重复，不把它称为20000个不同程序的穷举。
- 另核3组结构性质：同一方案两次实例化得到不同的新变量而每份内部保持共享；概括排除环境自由变量；替换组合把a经b更新为Int。

twice的实际统一轨迹是：t0与(t1→t2)；随后(t1→t2)与(t2→t3)；分解得到t1=t2、t2=t3。图与正文把t0、t1、t2、t3换成a、b、c、d便于手算。

这两份程序都由作者制作，因此交叉一致不构成非作者审查，也不是一般性数学证明。测试没有性能基准，不声称类型推导总是线性时间；没有执行被分析的程序，更不能从这些检查推断任意现实程序的运行安全、业务正确或终止性。
