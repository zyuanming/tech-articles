# 两箱水量与可观测性：模型、数据与重绘

正文：[read.md](read.md)。这里实际执行的是精确分数计算，没有搭建真实水箱、采集传感器数据或运行状态估计器。

## 模型与版本

- Python 3.12.14；标准库fractions.Fraction做精确有理数运算，没有随机种子，因为没有随机项。
- 水量单位升，每箱容量10升，每轮1秒；所有排水和交换均按轮初水量计算，一起更新。
- 外流为各箱水量的1/5；初始交换系数g=1/10，净转移为g乘以“左减右”，正表示左向右。
- 初态A=(8,2)、B=(2,8)、C=(5,5)。各自计算0至8秒共9个记录时刻。
- 已知输入分支在每轮末尾加(0.3,0.1)升，三个初态都接受同一序列；这不是把左右加水量设为相同。
- 只量左箱的分支回到零输入，观察者只用两次左箱读数和已知系数，不使用旧总量10升。A/B/C均独立恢复。
- 噪声分支比较g=1/10、1/100，自己的系数分别7/10、79/100。固定误差为第一次+1/50升、第二次−1/50升；不是随机测试。新候选对是(8,2)与(8,3)，不是前面A与B。
- 非零g时两次左量的观测表满秩；g=0时只有一条独立线索。所有例子的总量观测表秩为1。

## 运行

在文章副本目录执行：

```sh
python3 examples/run_model.py --output water-model-run-01
```

输出目录必须尚不存在。程序不联网、不安装包、不读取真实设备。它写出results.json、trajectories.csv、stdout.txt，保留断言检验结果。

本次原始输出：[stdout](originals/model-stdout.txt)；结构化结果：[expected-results.json](examples/expected-results.json)；[54行逐秒记录](examples/trajectories.csv)。CSV有一行表头，数据为2种输入条件 × 3个初态 × 9次记录，显示到小数点后8位。JSON同时保留精确分数与供显示的浮点数；证明相同使用分数，不依赖小数舍入。

程序直接实现排水和净转移，再分别核对总量的闭式规律、差值、已知输入下的相同输出、左箱两次读数恢复，以及固定误差的代数传播。图中的连接线只是连接离散记录，不证明秒间真实水流如何变化。真实水槽是否满足本模型，需要另行建模与实验，本文不作这种验证。

## 重绘与图像身份

在文章副本目录运行：

```sh
python3 examples/build_figures.py
```

需要已经安装的Pillow（本次12.3.0）、Noto Sans CJK Regular/Bold字体。脚本不自动安装软件或下载素材，使用examples/expected-results.json中的实际运行结果，绘制13张原创正文图及独立封面，并核对照片尺寸但不改写照片。

[figure-metadata.json](examples/figure-metadata.json)列出每图用途、身份和字号。原创图宽1062像素，最小字号36像素，缩到354像素时约12像素；这说明制图字号，不是对所有浏览器和平台显示效果的保证。
