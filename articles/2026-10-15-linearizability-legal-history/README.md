# 线性一致性：有限历史检查与受控线程示范

正文：[read.md](read.md)。本目录的代码、历史数据、实验图和机制图均为原创教学材料，不是生产数据库评测。

## 重跑

在本目录执行：

```sh
python3 examples/check_history.py --output run-new
python3 examples/build_figures.py --output redraw-new
```

输出目录必须尚不存在。第一条仅用Python标准库；本次运行Python 3.12.14，无随机采样、无网络、无安装、无外部服务。每次输出results.json、两份CSV与stdout.txt。受控线程调度下事件序号和返回值可复现，但纳秒时间与Python版本字段随环境变化，不能要求整个results.json逐字相同。

第二条需Pillow以及已有Noto Sans CJK Regular/Bold字体，字体集合index=2。它读取保存的expected-results.json，输出13幅正文PNG、独立cover.png和figure-metadata.json。公开正文图在assets内，封面在本目录；重绘目录采用平铺文件名。原图宽1062像素，最小文字36像素，缩到354像素宽为12像素。图不是网页/终端截图。

## 模型和边界

检查对象只有一个寄存器，初值0，值域{0,1}。完整操作用唯一的调用/返回事件序号表示，调用在前。写入成功更新值，读取返回当前值且不更新。输入以已配对的操作列表提供，未实现任意原始分布式日志的关联/校时/解析器。事件序号用整数；实际线程时间来自同一进程的perf_counter_ns。每轮CSV的elapsed_ns相对该轮记录器创建时刻，图9减去了首事件读数，以首事件为0。

complete_orders穷举所有完整操作排列，先检查真实先后，再从初值执行顺序规格。check枚举待定写的保留子集，为保留的写在末尾补确认，删除其余待定写，再检查扩展后历史的真实先后。补确认的次序不影响本实验的操作先后约束，因为全部补在最后一次调用之后。待定读明确不支持，超时/取消/失败码也没有自动映射。主例每个过程自己顺序调用；360份枚举把W、A、B视为独立过程各调用一次。

threaded_run用threading.Event规定先后，以Lock保护共享值。每次事件等待上限5秒，join上限6秒；线程异常或未终止会导致实验失败，不把不完整记录冒充成功。第一轮正常读取；第二轮人为注入B返回旧缓存0，非自然故障、非网络丢包。

结果：正常轮唯一见证A→W→B，错误轮无见证。9个固定案例涵盖普通合法/非法历史、过期读、两个端点排序反例、待定写必要/可选/不许影响过去以及两读重叠。360份穷举历史＝90种端点顺序×4组读取结果，246份合法、114份非法。额外独立图算法用实时边与读值边检测环，360份判定均一致。图算法只对初值0、一次写1、两个0/1读的范围成立。

有限实例的成功检查不构成任意实现的正确性证明；没有测量吞吐量、分布式时钟误差、网络分区、持久性、崩溃恢复或生产接口。

## 文件与许可

- examples/check_history.py：完整标准库实验和检查器。
- examples/expected-results.json：本次实际运行记录，含手工构造案例与真实线程事件，二者字段分开。
- originals/*.csv、experiment-stdout.txt：本次可公开的实验原始输出，不是外部史料。
- examples/build_figures.py：原创图的确定性重绘程序。
- examples/figure-metadata.json：图的职责、尺寸与最低字号。
