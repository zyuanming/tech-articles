# 太亮的地方，全挤在最后一格

逆光拍的窗外是一整块白，但相机其实记下来了——丢掉它的不是传感器，是最后那一步：8 位屏幕只有 256 格。这一篇不假设你知道什么叫色调映射，从「256 格怎么分」开始，用四条能手算的曲线把代价摊开：截断（什么都不做）在 1 以上每档只剩 1 个码值；Reinhard 的 `x/(1+x)` 让中灰保留 0.85 的对比度、到 8 倍亮度只剩 0.11；白点决定「多亮算白」；一条常见的 ACES 有理拟合反着来，暗部压暗近 5 倍、高光更早截断。最后用「连续渐变过去之后最长一段重复多长」量条带：截断 7171 个采样落在同一格，Reinhard 584。

## 复现

```
python3 examples/run_model.py      # 生成 examples/results.json（约 1 秒），打印 14 条自验
python3 examples/build_figures.py  # 生成 assets/ 与 cover.png（约 3 秒）
```

两个脚本都是确定性的，重跑得到相同的数字与图（`results.json` 9 536 字节）。只需标准库（画图另需 Pillow）：不用 NumPy，没有取随机数，没有计时。

## 结构

| 路径 | 内容 |
| --- | --- |
| `read.md` | 正文，9 张图按出现顺序编号 |
| `assets/01..09-*` | 正文用图（1062 px 宽），与 `examples/figure-metadata.json` 一一对应 |
| `cover.png` | 1080×1080 封面：同一段渐变在截断与 Reinhard 下的对比条 |
| `examples/tone.py` | sRGB 编解码、四条曲线、对数斜率、码值统计 |
| `examples/run_model.py` | 跑全部实验，写出 `results.json` |
| `examples/build_figures.py` | 画图，写出 `figure-metadata.json` |
| `examples/figkit.py` | 画图小工具（几何断言、字号换算） |

`tone.py` 的主要入口：

- `srgb_decode(v)` / `srgb_encode(v)`：IEC 61966-2-1 分段式，低段 12.92v，高段 1.055 v^(1/2.4) − 0.055。
- `code8(v)`：线性值 → 8 位码值，四舍五入。
- `clamp01(x)`：截断基线，`min(x, 1)`。
- `reinhard(x)`：`x/(1+x)`。
- `reinhard_white(x, white)`：`x(1 + x/w²)/(1+x)`，`w` 处正好输出 1。
- `aces_fit(x)`：`x(2.51x + 0.03)/(x(2.43x + 0.59) + 0.14)`，常用近似，不是官方 RRT+ODT。
- `loglog_slope(f, x, h=1e-4)`：「输入变一个 stop，输出变几个 stop」。
- `codes_in_range(f, lo, hi, samples=4000)`：一段输入里屏幕用出多少个不同的 8 位码值。
- `ramp_stats(f, hi, samples=8192)`：`{codes, longest_run, samples_per_code}`，最长重复段即色带宽度。

## 关于数字

正文里每个数都来自 `examples/results.json`，图也一样。数的都是亮度、码值与比值，不是耗时。可手算复核的地方：

1. sRGB 编码：0.18 → 0.46136 → 码值 118；0.5 光量 → 0.73536 → 码值 188；光量 0.214041 → 编码 0.5 → 码值 127。
2. Reinhard：0.18 → 0.15254（码值 109）；1 → 0.5；8 → 0.88889（码值 242）；16 → 0.94118（248）；1000 → 0.99900（255）。中灰要抬到 0.21951 才回到 0.18，比值 1.2195。
3. 白点 8：`8 × (1 + 8/64) / 9 = 8 × 1.125 / 9 = 1.0`。
4. ACES 拟合：0.18 代入得 `0.18 × (0.4518 + 0.03) / (0.18 × (0.4374 + 0.59) + 0.14) = 0.0867 / 0.3249 = 0.2669`（码值 141）；1 代入得 0.8038；0 处斜率 `0.03/0.14 = 0.2143`。
5. 对数斜率：`x/(1+x)` 的 log-log 斜率正好是 `1/(1+x)`——0.18 处 0.847，1 处 0.5，8 处 0.111。
6. 每档码值：1 到 8 之间，截断给 1 个（全 255），Reinhard 55 个，白点 8 给 67 个；8 到 16 之间分别是 1 / 7 / 1。
7. 条带：8192 个采样里，截断最长一段连续相同是 7171 个（87.5%），Reinhard 584，白点 8 是 316，ACES 拟合 1661（在暗部）。
8. 曝光：中灰抬一档，Reinhard 的码值从 109 到 141，两档 173，三档 202。

模型没做的事：没有读入任何真实 HDR 图片（全是单像素亮度的 1 维计算）；没有实现完整 ACES RRT+ODT；没有做局部算子实验（光晕只出现在决策表一行里）；没有做抖动，所以图 7 是不抖动时的最坏情况；没有讨论色度；没有观察者实验；没有测耗时。`sources.md` 里逐条写明，另外 ACES 那条拟合的一手出处本稿没有取到，所以全文只叫「ACES 拟合」。
