# 五台机器怎么决定「现在是什么」：可复算材料

正文：[read.md](read.md)。来源与许可：[sources.md](sources.md)。

这篇文章里的每一个状态、每一条日志、每一个计数——选举耗时、提交耗时、消息条数、孤儿条目、违规次数——都由本目录的代码**实际模拟出来**，不是从论文或别处抄的。模拟器只用 Python 标准库，约 940 行。

## 运行

环境记录见 [run-environment.json](examples/run-environment.json)。**全部代码只用 Python 标准库**，不需要安装任何东西（绘图另需 Pillow 与一款中文字体）。

在本篇目录中执行：

```sh
python examples/run_model.py        # 全部实验，写 results.json
python examples/build_figures.py    # 重绘全部正文图与封面
```

首次运行时的原始标准输出保存在 `originals/model-stdout.txt`。

## 模拟器覆盖了什么、没覆盖什么

覆盖：任期、选举、随机化超时、心跳、日志复制、快速回退、提交规则、选举限制、网络分区、成员变更、随机日程下的安全性检查。

**没有覆盖**：持久化与崩溃恢复的落盘顺序、日志快照与压缩、批量与流水线复制、只读请求的租约优化、Pre-Vote 与 CheckQuorum 等工程扩展、磁盘与网络故障模型。它是一台教学模型，不是可以拿去存数据的实现。

## 三个关键机制

### 1. 不变量是写成代码的，不是写在纸上的

`check_safety()` 检查四条性质：同一任期不可能有两个领导（**每一步都查**）、同索引同任期则前缀相同、两台都提交同一索引则内容相同、已执行序列前缀相同。

随机日程把崩溃、重启、分区、写请求混在一起跑。正文第 19 节引用的「400 个日程 0 违规」就是它跑出来的。

### 2. 检查器抓到了一个真实 bug，而且留了复现开关

第一次跑 300 个随机日程时出现了 1 次违规（种子 62）：**B 与 E 已应用的序列不同**——E 在索引 1 上执行了一条后来被覆盖、从未被多数派确认过的命令。根因是跟随者回复的是**自己整份日志的长度**，而不是「我们核对到哪个索引为止一致」，于是领导收到一个大于本次发送范围的数字，误以为那些条目已经在多数派手里。

修好之后，同一批日程 0 违规。为了让你能自己重现它，`Cluster.reply_rule = 'whole_log'` 会故意用回错误写法：

```python
import raft
raft.safety_sweep(400)                          # 0 违规
raft.safety_sweep(400, reply_rule='whole_log')  # 1 违规（种子 62）
```

### 3. 随机测试抓不到的那类 bug，正文也如实写了

把提交规则改错（允许提交旧任期的条目），400 个随机日程**依然是 0 违规**——Raft 论文 Figure 8 那个交错顺序太特殊，随机碰不上。正文第 15 节因此用手工构造的状态复现了它（`figure8()`），第 19 节则明确写了「随机测试能证明有 bug，不能证明没 bug」。
