## 两个实验设计上的返工

**其一，墓碑实验一开始是不可复现的。** 三次独立实验跑出来三个一模一样的数，看着像 bug。查下去发现三次循环共用同一个键序列，只是删除的位置不同——`find` 探测的路径完全由表的状态决定，而表的状态在三次实验里恰好被复制了。改成每轮各自生成键（`keys(4000, seed=500+cycle)` 与 `keys(2000, seed=900+cycle)`）之后，三组数变成 22.7 / 25.4 / 17.9，正文只引第一组，`sources.md` 里说明了另外两组的存在。

**其二，α = 0.98 的公式偏差差点被当成公式错误。** 第一版只在 m = 4099 上测，实测 575、公式 1250，差一倍多。当时的判断是「公式在高装载率下不成立」，准备把这一结论写进正文。加了 m = 65 537 的对照（实测 966.4）才看清：差的是表长，不是公式——4099 个槽在 98% 装载率下最坏情况被表长截断。正文因此把这一节写成「公式是渐近的，小表撑不起」，而不是「公式错了」。

## 再一轮：槽号、键号、探测次数标成行内代码

数字密集段 49% → 11.8%。51 段 / 平均段长 73.9 / ≤2 句段 35.3% / 句长标准差 13.1 / 最长句 67，`tools/refresh_article.py check` 报 `INVARIANTS_OK`。

上一轮留这项的理由是「这篇通篇是 α 从 0.5 走到 0.98、四种策略各走几步，数字就是论证」。理由成立，但它只否掉了「删数字」，没有回答「这些数字该怎么排」。这一轮改的是排法：

- **槽号和键号成组标码**：`插 15` 那一段变成「插 `15` 更惨，槽 `1`、槽 `2` 都有人，落到槽 `3`」。读者一眼能分出哪个是键、哪个是槽位。

- **实验参数标码**：`m = 4099`、`m = 65537`、`1500` 个不在表里的键、两次实验的装载率 `50%` 与 `89%`。
- **簇长那一组**：`407 格`、`1167 格`、`1925 格` 三个一组，后面接「将近半张表」一句总括，原来的对照关系一句没改。
